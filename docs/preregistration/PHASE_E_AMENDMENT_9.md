## Routes (SQL; every route runs in one transaction with `SET LOCAL`)
- **exact:** `enable_indexscan = off`, iterative off; `ORDER BY dist, id LIMIT k` (Amendment 2 exact plan: Seq Scan or Bitmap Heap Scan).
- **iterative (default):** `enable_indexscan on, enable_seqscan/bitmapscan/sort off, hnsw.iterative_scan = relaxed_order`, `max_scan_tuples` 20000, `scan_mem_multiplier` 1, inside `WITH c AS MATERIALIZED (... ORDER BY dist LIMIT k) SELECT ... FROM c ORDER BY dist, id`. **Tuned:** same with `hnsw.max_scan_tuples = 100000`, `hnsw.scan_mem_multiplier = 4`. These values come from the 10 Oct exploratory diagnostic (`exploratory_diag_iterative.py`, commit `a1476c8`, hm_clothes_100 lo3/lo4, vectors 0-19, untimed; relaxed recall 0.925/0.940), i.e. chosen on in-sample cells: **held-out cells are the test.**
- **hnsw (forced, iterative off):** Amendment 2 forced-hnsw settings, plain `ORDER BY dist LIMIT k`; this is "default HNSW + WHERE" (what FinQA's `post-filter` executed).
- **planner_iterative:** `RESET` all `enable_*`, `relaxed_order`, CTE form; plan recorded, no expectation (as Amendment 6 A6).
- **Guard (where stated):** if the iterative/hnsw query returns < k rows, run exact and return its rows; if exact also returns < k, flag `filter_smaller_than_k`.
- **Pre-flight** plain `EXPLAIN` for every table x filter x route before any measured query: exact = Seq/Bitmap Heap Scan; iterative/tuned/hnsw = Index Scan on `*embedding_idx` (inside the CTE; a Sort above the CTE is allowed); probe = Index Scan on `*embedding_idx`. Any mismatch aborts.

## Decision rules
- **Estimate:** `EXPLAIN (FORMAT JSON) SELECT 1 FROM t WHERE f` top-node "Plan Rows" / N, N = `pg_class.reltuples`. reltuples = -1 or <= 0, or no Plan Rows -> **error** (no fallback). s_est < T/2 -> exact; s_est > 2T -> iterative; else (band, edges T/2 and 2T included) capped count `SELECT count(*) FROM (SELECT 1 FROM t WHERE f LIMIT floor(T*N)+1) x`: count == limit -> iterative, else exact.
- **Local probe** (VecAdvisor's idea, our implementation): unfiltered HNSW top m = 100 on the existing cosine index (`ef_search = 100`, iterative off, probe only); p = rows passing f. p < k -> exact, else iterative + guard. Probe latency recorded.
- **Modes:** `router` (T_default, band, iterative + guard) = the final router; `router_tuned` (T_tuned, tuned + guard); `router_no_guard`; `router_always_count` (capped count always, no estimate); `fixed_t_0_1` (router logic, T = 0.1); `local_probe`; `router_plus_probe` (router, but iterative with p < k -> exact); `iterative_tuned` (tuned + guard); `default_hnsw` (hnsw, no guard); `planner_iterative`; `retry_exact` (hnsw + guard; Amendment 6 A8); `always_exact`; `always_iterative` (default iterative, no guard; P6); `llm_router` (D5); `oracle` (per cell, fastest passing of always_exact, always_iterative, iterative_tuned, default_hnsw, retry_exact, planner_iterative; computed offline).

## Calibration (the method; Task 3, on the D2 session only)
Grid = the 13 in-sample selectivities. Per table: s_exact_max = largest grid s where exact passes; s_iter_min = smallest grid s from which the iterative variant (+ guard) passes at it and every higher grid point; safe interval = (lower neighbour of s_iter_min, s_exact_max] (if s_iter_min is the smallest grid point, the lower endpoint is that point itself); T = geometric mean of the endpoints. **Pooled:** a grid point passes for a route only if it passes on all five tables; **pooled T is used.** Empty interval (lower endpoint >= s_exact_max) -> report the gap; T = the grid point with the fewest failing cells under "exact if s < T else iterative + guard" (ties -> smaller). Run twice: default iterative (T_default) and tuned (T_tuned). On H&M this re-applies the procedure to data that earlier gave (0.0478, 0.2038]; **held-out cells are the test.** Output `config/policy_v3_hm.json`.

## Decisions
- **D1** H1 is retrospective: already seen, stored iterative under-fill lo1 18-20/20 on every table; hm_clothes_100 lo3 1/20, lo4 8/20; hm_clothes_50 lo2 0/20 with mean recall 0.865.
- **D2** One quiet session on the 65 in-sample cells: exact, default iterative + guard, tuned iterative + guard; per (cell, vector, route) one normal execution (rows, recall), one warm-up, 5 timed `EXPLAIN (ANALYZE)` Execution Times, median (the stored runs' metric). Guard latency = iterative median + exact median of the same vector in this session; guard rows = exact's rows. Order of cells, vectors and routes shuffled with `random.Random(20261030)`. Reason: stored in-sample runs were under unrecorded load and a quiet rerun of one held-out cell gave 122.8 vs 528.4 ms with seed, order and time also different, so the cause is undetermined (DEVIATION_LOG); no load effect of a given size is claimed. Stored values reported per cell as reference, not used.
- **D3** Exact top-10 ids recomputed once per (cell, vector) for all three sets, `enable_indexscan = off`, `ORDER BY dist, id`; stored in `outputs/ground_truth_hm/` (checksummed); used for all new recall. Reproducibility: forced-hnsw re-run on the 3 in-sample cells with the lowest stored forced-hnsw mean recall; per-vector recall vs stored reported.
- **D4** VecAdvisor 0.1.0a6 is **not scored** (`outputs/vecadvisor_check_2026-10-30/`): it cannot see the HNSW index (on the expression `embedding::halfvec(2048)`, needed because pgvector caps HNSW on `vector` at 2,000 dims); `--vector "embedding::halfvec(2048)"` crashes it; its local probe is skipped and it falls back to global selectivity; it ranks only partial and exact (lo3: partial, exact; idx3: exact); its SQL and suggested index assume L2 while the index is cosine; making the index visible needs DDL, ruled out. `calibrate-db` uses only TEMP tables on synthetic data; `recommend` runs no DDL.
- **D5** llm_router: Gemini 3.8 Flash (`config/generation.json`: temperature 0, thinking LOW, 2048 max output), FinQA system prompt `NAIVE_INFORMED_ROUTER_SYSTEM` verbatim (it names "company ticker and fiscal year"; kept unchanged), route vocabulary pre-filter -> exact, post-filter -> default_hnsw (no guard). H&M has no natural-language questions: it decides from a description of the filter; user message `Metadata filter to be applied: <filter>\nQuestion: find the 10 catalogue items most similar to the query item.` One call per held-out filter (10 calls), held-out cells only; unparseable -> route failure, cell fails.
- **D6** All new iterative runs use `SET LOCAL` + MATERIALIZED CTE; pre-flight as above; stored runs reference only.
