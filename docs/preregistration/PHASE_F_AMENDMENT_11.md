## 2. Router: policy_v3.1

- **policy_v3.1** = policy_v3 of Amendment 9 with one added rule (`src/phase_e_router/policy_v3_1.py`): before the planner estimate is used, every column the filter references must have planner statistics (a `pg_stats` row for a plain column; for a JSONB or expression filter, an extended-statistics expression statistic or the statistics of an expression index on the same expression). If any is missing, the estimate is skipped and the capped count `SELECT count(*) FROM (SELECT 1 ... LIMIT floor(T*N)+1)` decides (count == cap -> iterative, else exact); the trace records `estimate_skipped_no_stats`. Everything else is as v3 in Amendment 9 (band rule quoted in section 3, guard, routes, SQL), unchanged.
- **Why the rule:** on FinQA the planner returned Plan Rows = 1 for every ticker-year filter because no statistics exist on `metadata->>'ticker'` / `'year'` (`reports/finqa_router_v3_route_check_2026-10-31.md`), so the estimate carried no information.
- **Checks before this tag** (`outputs/edgar_eval_v31_checks_2026-11-01/`): (a) every Amendment 9 H&M filter (in-sample 13, held-out 5 + 5) x 5 tables x {T_default, T_tuned}: 230 decisions, **0 route differences** from v3, the rule fired 0 times (all H&M filter columns have `pg_stats` rows); (b) the 50 frozen FinQA questions: the rule fires on **50/50**; the capped count (20-697 rows vs cap 2,554) routes all 50 to exact, as v3 did. On `edgar_chunks` all three filter columns have statistics, so the rule is not expected to fire.
- **Two router modes:** `router` = v3.1 with T calibrated on `edgar_chunks` (section 3, `config/policy_v3_1_edgar.json`); `router_hmT` = v3.1 with the frozen H&M T = 0.07119 (`config/policy_v3_1_hm.json`, copied from `config/policy_v3_hm.json`), iterative default + guard: the **transfer test**. Module config `config/router_edgar.json` (table, columns, `embedding <-> %s::vector(1024)`, L2, k = 15, ef_search 40, iterative settings as H&M).

## 3. Calibration on edgar_chunks (Task 3; no paid call)

Amendment 9's procedure, pass rule and grid, applied to `edgar_chunks`. Quoted verbatim from `PHASE_E_AMENDMENT_9.md`:

- Pass rule: "**Pass rule** = `PHASE_A_ARMS_PROTOCOL.md` Amendment 1, A3: mean recall@10 >= 0.90 and median of the 20 per-vector medians <= 500 ms, all 20 vectors valid (error/timeout/route failure = not passing)."
- Interval and T: "Grid = the 13 in-sample selectivities. Per table: s_exact_max = largest grid s where exact passes; s_iter_min = smallest grid s from which the iterative variant (+ guard) passes at it and every higher grid point; safe interval = (lower neighbour of s_iter_min, s_exact_max] (if s_iter_min is the smallest grid point, the lower endpoint is that point itself); T = geometric mean of the endpoints." and "Empty interval (lower endpoint >= s_exact_max) -> report the gap; T = the grid point with the fewest failing cells under "exact if s < T else iterative + guard" (ties -> smaller). Run twice: default iterative (T_default) and tuned (T_tuned)."
- Band rule (unchanged): "s_est < T/2 -> exact; s_est > 2T -> iterative; else (band, edges T/2 and 2T included) capped count `SELECT count(*) FROM (SELECT 1 FROM t WHERE f LIMIT floor(T*N)+1) x`: count == limit -> iterative, else exact."
- Session (D2, verbatim): "per (cell, vector, route) one normal execution (rows, recall), one warm-up, 5 timed `EXPLAIN (ANALYZE)` Execution Times, median (the stored runs' metric). Guard latency = iterative median + exact median of the same vector in this session; guard rows = exact's rows." Routes: exact, default iterative, tuned iterative, probe; Addendum 1 early stop and Addendum 2 quiet rule apply unchanged; pre-flight plain `EXPLAIN` of every cell x route as Amendment 9 (exact: no HNSW; iterative: Index Scan on `edgar_chunks_embedding_idx` inside the CTE).

**Stated differences:** (1) one table, so the "pooled" interval is that table's; (2) **query set** = the 20 calibration questions of Task 1 (`calibration_queries.csv`, vectors from `question_embeddings.json`), disjoint from the 40 evaluation questions; (3) **grid** = the 13 values of `config/policy_v3_hm.json` "grid" (0.000124 ... 0.4705); each grid filter is `cik IN (...)`: the 433 CIKs (sorted) are shuffled with `random.Random(20261102)` once per grid point (in grid order, one generator), then walked in that order, adding a CIK whenever it brings the matched row count closer to s x 158,308; the achieved selectivity (count / 158,308) is recorded and used as the cell's s; (4) **k = 15 and recall@15** against exact search (exact top-15, `enable_indexscan = off`, `ORDER BY distance, id`), matching the answer pipeline; recall@10 is also recorded but not used for the pass rule; (5) order of cells, vectors and routes shuffled with `random.Random(20261102)`; (6) these cik sets are **not** query-correlated (section 7).

Output `outputs/edgar_calibration_2026-11-01/` and T_default / T_tuned written to `config/policy_v3_1_edgar.json`, tag `phase-f-calibration-edgar-2026-11-01`. If the procedure gives no interval, the empty-interval rule quoted above applies (it is Amendment 9's rule); if it cannot be applied (e.g. a route has no valid result at any grid point), the run stops and is reported.

## 4. Retrieval comparison (Task 4; no paid call except llm_router)

All 160 pairs x these modes, k = 15, live on `edgar_chunks`:

- The 14 modes of `src/phase_e_router/retriever.py` (`router`, `router_tuned`, `router_no_guard`, `router_always_count`, `fixed_t_0_1`, `local_probe`, `router_plus_probe`, `iterative_tuned`, `default_hnsw`, `planner_iterative`, `retry_exact`, `always_exact`, `always_iterative`, `llm_router`), with the band modes under policy_v3.1 (`policy_v3_1.retrieve`) at the edgar T; plus **`router_hmT`**. The Amendment 9 `oracle` is not a mode of `retriever.py` and is not computed.
- **`llm_router`** (Amendment 9 D5): Gemini 3.8 Flash (`config/generation.json`), `NAIVE_INFORMED_ROUTER_SYSTEM` verbatim, user message `Metadata filter to be applied: <filter>\nQuestion: <question>` (filter written as `cik = '...' AND fiscal_year = ... AND section = '...'`); one call per pair (160), decision cached; pre-filter -> exact, post-filter -> default_hnsw (no guard); unparseable -> route failure (pair fails, answer abstained). LLM time reported separately; its cost counts toward the cap.
- **`vecadvisor`**: VecAdvisor 0.1.0a6 (`.venv-vecadvisor`). **Amendment 9 defines no adapter** (D4: VecAdvisor was "**not scored**" on H&M); this amendment defines one (`src/phase_f_edgar/vecadvisor_adapter.py`): per pair, `vecadvisor recommend --table edgar_chunks --vector embedding --query <filter with literals> --q-vectors <the pair's question vector> --limit 15 --ef-search 40` (other options default; read-only, no DDL); decision cached per pair, its wall time reported separately (as llm_router). The executed strategy is VecAdvisor's top-ranked candidate; if that candidate requires a new database object (partial or partition index), the pair is recorded **`vecadvisor_unavailable`** (reason `requires_new_object`) and VecAdvisor's next-ranked candidate that needs no new object is executed (its own ranking). If `recommend` errors or returns no usable candidate, the pair is recorded `vecadvisor_unavailable` (reason `error`) and **exact** is executed, the fallback VecAdvisor's own output names ("exact is the recall-safe fallback"). Strategies run with VecAdvisor's own parameters, no guard: `exact` -> exact route; `iterative_relaxed` / `iterative_strict` -> `hnsw.iterative_scan` relaxed_order / strict_order, its ef_search and max_scan_tuples, MATERIALIZED CTE; `postfilter` -> iterative off, its ef_search. Our `local_probe` is never substituted.
- **Prior-system rules** (Amendment 6 / 7 implementations): **VBASE** exact if s < 0.18; **Milvus** exact if s <= 0.05; **Qdrant** exact if matching rows < 10000 KB / 4 KB = **2,500** rows (`full_scan_threshold_kb` 10000, vector size 1024 x 4 = 4,096 bytes; as Amendment 7's 2,500 for 1024-d); else default iterative (relaxed_order, no guard; the Amendment 6 "iterative-relaxed" arm). s = exact count / 158,308 (Amendments 6/7 use the exact count), computed per query and **included in the latency**. **Gan & Wang (B4/B4b) are excluded:** their classifier was trained on H&M features.
- **Measures per pair and mode:** route, rows returned, recall@15 against exact top-15 (`enable_indexscan = off`, `ORDER BY distance, id`), recall@10, gold-chunk hit (any returned id among the pair's gold ids), under-fill (< 15 rows), guard firing, latency = end-to-end wall-clock of `retrieve()` (includes stats check, estimate, count, probe, guard; llm and vecadvisor decision time separate), 1 normal execution + 1 warm-up + 5 timed, median, Addendum 1 early stop (median of the first 2 > 1,500 ms), Addendum 2 quiet rule at start, host load every 5 min, pre-flight plan check. Order of pairs and modes shuffled with `random.Random(20261105)`.

## 5. Answer runs (Task 5; paid)

- Gemini 3.8 Flash on Vertex with the Amendment 1/2 settings: temperature 0, `thinking_level` LOW, 2,048 max output tokens, `ANSWER_SYSTEM` verbatim ("You solve FinQA questions. ..."), user message `Evidence:\n<passages>\n\nQuestion: <question>`. **Only stated change:** each passage line is `[<company_name or "CIK <cik>"> | FY <fiscal_year> | Item <section>] <chunk text>` (instead of `[query_id::key]`), because the chunk text names the company in only a minority of chunks (12 of 60 gold chunks).
- **Passages:** the rows of the mode's normal execution in Task 4, in returned order; a row whose text equals an earlier row's text is dropped (Amendment 1 "distinct" by text), **without over-fetching** (Amendment 1 over-fetched to reach 15 distinct); the number of distinct passages is logged. Exact duplicates are 2.2 % of rows (154,824 distinct texts of 158,308).
- Answers for every mode of section 4; when two modes return the identical ordered passage list for a pair, the answer is generated once per pass and reused (reuse map recorded). llm_router route failures and modes with 0 rows send the question with an empty evidence block.
- **Passes:** a pilot of 5 calls (seeded `random.Random("20261101-pilot")`, excluded from analysis), then the projected cost of 1, 3 and 5 passes (pilot mean cost per call x unique calls per pass); the largest of 5, 3 or 1 passes whose projection is **at most USD 4.50** and keeps the session total under USD 6.00 is used; the decision is written to the run log before the main run. If even 1 pass exceeds this, the run stops (stop condition). Single attempt per call (Amendment 4 Addendum 1); a failed call counts as abstained and is listed. Pass order: items shuffled with `random.Random(20261105)`.

## 6. Scoring, classes, predictions, statistics

- **Primary score:** Amendment 2 primary scorer (`scoring.score_answer(rule="primary")`) on the number span of the answer (`verify_questions.first_number`) against `gold_number`.
- **Classes (each answer exactly one):** `correct`; `abstained` ("not answerable", no number, or a failed call); `wrong_in_context` (the answer's normalised number, rule A of `verify_questions.number_in_text`, appears in at least one passage of the prompt); `wrong_not_in_context` (appears in none: the **automatic invented-number proxy**).
- **Validation:** a seeded sample (`random.Random(20261103)`) of up to 40 wrong answers (pass 1), half from `router`, half from `default_hnsw` where available (the rest from the other if one has fewer), labelled S / C / N by the Amendment 5 definitions, verbatim: "**S** = the answer number appears in the retrieved text; **C** = the answer can be calculated from numbers in the retrieved text; **N** = the answer is not supported by the retrieved text." Labels are drafted by the AI assistant and checked by the author; the proxy's agreement with the checked labels (N vs `wrong_not_in_context`) is reported after the labels are returned.
- **Predictions (stated before any edgar measurement):**
  - **P1:** router recall@15 at least 0.90 on at least 95 % of pairs.
  - **P2:** router accuracy is non-inferior to always_exact: pooled over passes, per-pair mean correctness, difference router − always_exact, cluster-bootstrap 95 % CI (below) with lower bound above **−0.10** (the Amendment 3 method with the 40 questions as resampling units).
  - **P3:** router accuracy is higher than default_hnsw: exact McNemar on pass 1, the 160 pairs as units, p < 0.05 (two-sided) with more router-only-correct pairs.
  - **P4:** router's `wrong_not_in_context` rate is lower than default_hnsw's (descriptive, with CI).
  - **P5:** router median latency is below always_exact's at the year+section and section breadths (descriptive).
  - Everything else is descriptive. All results are broken down by breadth.
- **Uncertainty:** cluster bootstrap with the 40 questions as clusters (a question's four pairs move together), 10,000 resamples, `numpy.random.default_rng(20261104)`, percentile intervals.

## 7. Known limits (stated before any measurement)

- Question filters on cik are **query-correlated**: each question names its company, so the gold company's chunks are far closer to the question than random rows; local selectivity is much higher than global. The calibration uses uncorrelated cik sets; calibration (uncorrelated) and comparison (correlated) results are reported side by side.
- Questions always name the company even under the broad filters (year+section, section), so those pairs test whether retrieval finds the company from the question text.
- Only identical-text chunks are gold; other chunks may hold the answer (`F_alt_source` of the question checks).
- The question-drafting model and the answer model are both Gemini; `ANSWER_SYSTEM` still says "FinQA" (kept verbatim).
- One corpus, 40 questions; latency on one desktop under the quiet rule; the answer runs have at most 5 passes of identical inputs (generation noise, not new data).
- VecAdvisor's adapter and the prior-system rules are our re-implementations of published behaviour.
- The H&M tables were never ANALYZEd under Amendment 9 but have `pg_stats` rows (created before Amendment 9); `edgar_chunks` was VACUUM ANALYZEd on 2026-11-01.
